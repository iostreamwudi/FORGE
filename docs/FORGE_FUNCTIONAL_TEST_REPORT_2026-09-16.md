### Coach 超时专项回归（2026-09-16 11:32）

- 将 Web 客户端、API Provider 请求超时统一从 60 秒提高到 240 秒；FORGE 反向代理的 Coach API 等待时间调整为 300 秒，并保留 15 秒 SSE 心跳。
- 远程 `pnpm typecheck` 和 Web 构建通过，API 重启后 `/healthz` 正常。
- 当前浏览器使用原有唯一标签发送真实 Coach 请求，12.5 秒完成并写入云端，没有出现“没有成功连接到 FORGE”。Provider 状态仍显示 `deepseek-v4-pro`。
- 本次回归还暴露出一个独立的回答一致性问题：某条普通训练问题返回了历史动作调整内容；这是模型/长历史上下文污染问题，不是连接超时，需单独修复。

最关键的用户问题“换账号后在 Coach 里确认加入食物池但食物没有出现”已完成真实复现和闭环验证：

1. 使用第二个真实账号登录。
2. 初始食物池为 0 项。
3. 在 Coach 输入“把鸡胸肉加入食物池”。
4. 真实模型返回待确认营养分析卡，而不是直接伪造写入。
5. 点击“确认加入食物池”。
6. 进入食物池后看到真实写入的鸡胸肉和营养数据。
7. 删除该测试食物后，第二个账号回到 0 项。
8. 切回主账号后，主账号仍保持 7 项食物。

因此，当前这条“Coach 确认加入食物池”闭环在第二个已有账号上通过。需要注意：`demo@forge.iamwudi.ltd` 在服务端没有快照和食物数据，如果切换到该账号，食物池为空是当前真实数据状态，不是前一个账号的数据被复制过去。

## 2. 结果定义

- **PASS**：实际操作完成，且页面、服务端或数据库结果与预期一致。
- **FAIL**：实际操作发现功能错误、误报、数据未落库或关键交互失败。
- **WARN**：功能可用，但存在明显商业化风险、边界不清或稳定性问题。
- **BLOCKED**：入口存在，但测试被真实服务能力、数据覆盖或外部配置阻断。
- **SKIPPED**：涉及不可逆删除、账号注销、全设备踢出、昂贵模型调用等破坏性动作，只测试了确认层或入口。

### 多账号专项结论

当前数据库只读核对结果：

- 主账号：7 项食物、9 条饮食记录、12 组训练计划、Coach 历史存在。
- `1234@163.com`：测试结束后 0 项食物，未残留主账号食物。
- `demo@forge.iamwudi.ltd`：无快照、无 Coach 数据、无食物池数据。

代码中 Web 快照使用固定 localStorage key `forge.snapshot.v2`，读取后会校验快照中的 `profile.id`。目前第二账号闭环证明云端恢复和账号隔离在正常路径上成立，但仍应把本地缓存按用户 id 分桶，并为“新账号无快照”增加明确初始化状态，彻底消除切换账号后旧快照、空首页和刷新竞态的风险。
