# FORGE C 端产品与界面设计决策

> 这是一份可迭代的设计决策记录，用来约束体验方向，不冻结未来功能。早期原型曾使用 Mock / 内存状态；商业化实现必须接入真实账号、同步和通知基础设施，当前缺口统一记录在 `FORGE_UIUX_OPTIMIZATION_ROADMAP.md`。

## 1. 商业化产品判断

FORGE 的核心不是“记录训练的工具”，而是“每天告诉用户下一步做什么的训练与恢复产品”。因此每个页面都遵循：

1. 先给结论或下一步动作。
2. 再给为什么，以及可展开的细节。
3. 最后给设置、历史和账户管理。

当前底部导航收敛为五项：今日、训练、教练、进展、我的；智能教练固定在正中，“我的”固定在最右侧。饮食作为 Today 的高频摘要和 Coach 的可执行建议出现，详细饮食页仍可从 Today 进入，不占用一级导航位置。

## 2. 账号与个人中心范围

### 账号入口

- 欢迎 / 登录：邮箱、密码、忘记密码入口；登录按钮是唯一主 CTA。
- 注册：邮箱、密码、确认密码；明确密码要求和错误位置。
- 后续接入：验证码登录、Apple / 微信等第三方登录，但本轮不伪造服务端能力。

### 我的 / 个人中心

- 个人身份：头像、姓名、账户状态、切换账号。
- 目标与今日状态：进入已有的目标、体重、睡眠、疲劳、酸痛编辑页。
- 训练偏好：训练日、单位、默认休息时间（先展示入口，逐步接入）。
- 账号与安全：登录方式、密码、设备管理（本轮为可访问入口）。
- 数据与隐私：数据来源、导出与删除说明（本轮为明确反馈入口）。
- 帮助与反馈：问题反馈、版本信息。
- 退出登录：使用确认反馈，不能误触即退出。

## 3. 字体层级

当前问题不是所有字都“大”，而是页面标题、卡片标题和指标数字的权重差距不够稳定，导致像个人工具的堆叠界面。统一 Token 调整为：

| 层级 | 用途 | 字号 / 行高 |
| --- | --- | --- |
| Display | 训练总结的关键数字 | 40 / 44 |
| H1 | Hero 决策标题 | 28 / 34 |
| Title | 页面标题 | 26 / 32 |
| H2 | 卡片核心指标 | 21 / 27 |
| H3 | 卡片标题、动作名 | 17 / 23 |
| Body | 正文与解释 | 15 / 22 |
| Caption | 辅助信息 | 13 / 18 |
| Label | 小标签与导航 | 12 / 16 |

页面仍保留足够对比度和触控面积；压缩的是视觉噪音，不压缩 44pt 触控目标和 CTA 高度。

## 4. 个人中心的用户闭环

```text
Today 头像 → 我的 → 目标与今日状态 → 保存 → Today 即时更新
                    ↘ 账号与安全 → 登录 / 注册
```

首次打开默认进入 Today，不强制注册打断首个训练价值；当用户主动进入账户中心时，再提供登录和注册。这符合“先体验价值，再建立账户关系”的消费级路径。

## 5. 本轮验收

- 390×844 与 360–430dp 不横向溢出。
- 页面标题不超过一行，正文默认 15pt，核心数字只在关键位置使用 H1 / Display。
- 账户页面所有输入有可见标签、错误靠近字段、按钮最小 54pt。
- 所有返回行为可预测，个人中心不改变五项主导航结构。
