# FORGE UI/UX 优化路线

> 这份路线来自 `ui-ux-pro-max` 审计，按 P0 → P1 → P2 执行。每完成一批，必须通过 TypeScript、Lint，并在 360×800 与 390×844 进行运行态检查；随后调用两遍 `ui-ux-pro-max`，分别验证已完成项和新增需求。

## 当前结论

FORGE 已完成视觉基线、五项主导航、Today → Active Workout → Summary → Coach 的核心体验闭环。当前主要问题不是缺少更多页面，而是设计规范漂移、Mock/内存数据造成的可信度问题，以及原生无障碍验收尚未完成。

## 当前需要的外部验收输入

以下事项无法由当前客户端仓库凭空完成；在提供真实依赖前，客户端会继续保持诚实的未连接/待处理状态，不创建假数据：

- 部署可访问的 HTTPS FORGE API 地址，以及注册、登录、会话恢复、登出、找回密码、账号删除、Coach、动作库、营养库和同步接口的正式契约；数据导出交付的服务端实现已在本地 API 完成，但仍需正式 HTTPS 域名验收。
- 同步服务的版本号/冲突合并策略，以及离线队列逐条提交、服务端回读和跨设备恢复接口。
- Coach 服务端流式响应、历史回读/删除、consent audit、撤销即时生效、语音转写和数据保留/删除策略。
- iOS Apple Developer/HealthKit 签名与真机、Android Health Connect 真机或模拟环境，用于验证权限弹窗、撤销回读、后台增量同步、VoiceOver/TalkBack、Dynamic Type、横屏和安全区。
- 正式隐私政策、健康数据处理说明、AI 数据使用与保留期限，以及 onboarding/冲突处理/后台自动同步的产品决策。
